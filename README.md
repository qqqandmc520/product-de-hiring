## 安装

仓库根目录就是完整技能目录，包含`SKILL.md`、`agents/`、`references/`、`assets/`与`scripts/`。安装保留Git关联，后续可以直接拉取更新。

在目标电脑已配置Git、且已登录有权读取此仓库的GitHub账号后运行（仓库地址取当前页面Code中的HTTPS地址）：

```bash
git clone https://github.com/qqqandmc520/product-de-hiring.git "$HOME/.codex/skills/product-de-hiring"
```

若设置了自定义`CODEX_HOME`，将安装目录改为其`skills/product-de-hiring`。若已有同名技能，先核对本地改动并备份迁移，不直接覆盖；把备份放在技能目录之外，避免被重复发现。私有仓库需要仓库所有者事先授予使用者访问权限。

也可以让Codex操作：“把这个GitHub仓库作为product-de-hiring技能安装，保留Git关联便于后续拉取；若已有安装，先核对并备份迁移。”

安装后在新会话使用`$product-de-hiring`。若当前技能列表未刷新，重新打开会话。

## 拉取更新

```bash
git -C "$HOME/.codex/skills/product-de-hiring" pull --ff-only
```

`--ff-only`避免自动产生合并提交；如果本地修改与远端更新冲突，保留改动并先核对，不使用强制重置覆盖。技能不会自行定时更新；按需拉取并在新会话使用新版本。

可以直接告诉Codex：“从GitHub更新product-de-hiring技能，先核对本地修改，保留未提交内容。”招聘记录、岗位画像实例与生成报告应保存在部门工作目录中，不存入此技能仓库，避免与规则更新混杂。

## 首次使用

最短开场：“使用$product-de-hiring，帮我筛选这些简历，JD和简历在这个目录。”

没有正式JD也可说明产品服务谁、解决什么问题、此人负责什么，由技能整理岗位画像。技能按当前任务提示必要材料，复用已提供内容，通常每轮只补问1–3个关键问题。

| 当前环节 | 最少输入 |
| --- | --- |
| 简历筛选 | 岗位依据＋候选人履历材料 |
| 候选人专属面试准备 | 岗位依据＋候选人履历/项目/已有记录之一；缺候选人材料可先做通用提纲 |
| 面试后评估 | 岗位依据＋可辨发言人、包含实际问题和回答的记录；简历有则补充 |
| JD修订/起草 | 现行JD或岗位背景；招聘反馈有则提供 |

## 维护与版本

维护者修改技能、引用资料或模板后，更新版本记录并检查：

```bash
python3 scripts/read_model.py --verify
```

有候选人接续记录时，可在其所在工作目录按实际路径运行`scripts/case_tools.py check`。它只检查记录结构及引用，不判断事实真伪或候选人是否合适。安装环境提供`skill-creator`时，可再运行其`quick_validate.py`检查技能入口。

将检查通过的修改提交并推送到main后，使用者可按上文拉取。团队需要复查历史判断时，记录当时的技能版本、能力模型版本、岗位画像版本和Git提交号。仅拉取规则更新不会重写已有评估。

本仓库不包含真实候选人简历、纪要、评价或内部业务数据。维护时只提交通用规则、空白模板、虚构案例与明确的能力来源；不要把工作目录整体提交进来。

## 能力依据与使用边界

随包能力来源快照为313页汇编：总纲V0.2、P1 V1.1、P2–P7 V1.0，构建于2026-08-31。招聘流程、行为锚点、证据状态和决策方式属于应用建议，不是原模型定义或已发布的公司招聘制度。

已完成结构检查与情景自查；跨部门评估一致性仍需独立试评验证。技能提供可复查的招聘建议，最终决策由招聘团队作出。
