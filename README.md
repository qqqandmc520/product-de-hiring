# 产品领域专家招聘全流程

技能名：`product-de-hiring`｜当前技能版本：v0.4.1｜Git版本标记：v0.4.1。

依据同一套产品领域专家七项能力，贯通简历筛选、面试准备、面试后评估和JD修订。各部门配置岗位用户、任务、责任与独立业务要求，共用证据与判断口径。

本包是通用招聘框架，不内置具体产品方向、JD或行业题库。使用方提供产品背景、用户任务和岗位责任；缺少JD时通过少量必要问题逐步形成。具体行业、技术路线、指标、管理职责、要求层级和面试场景均由本次岗位确定，不从历史岗位或示例继承。能力原件案例仅用于解释定义，不构成默认任职要求。

## 安装

仓库根目录就是完整技能目录，包含`SKILL.md`、`agents/`、`references/`、`assets/`与`scripts/`。安装保留Git关联，后续可以直接拉取更新。

本仓库公开可读，查看、下载和HTTPS克隆无需登录GitHub，也无需申请仓库访问权限。在目标电脑已配置Git后运行：

```bash
git clone https://github.com/qqqandmc520/product-de-hiring.git "$HOME/.codex/skills/product-de-hiring"
```

若设置了自定义`CODEX_HOME`，将安装目录改为其`skills/product-de-hiring`。若已有同名技能，先核对本地改动并备份迁移，不直接覆盖；把备份放在技能目录之外，避免被重复发现。更新技能同样无需GitHub登录；修改仓库内容仍需要维护者权限。

也可以让Codex操作：“把这个GitHub仓库作为product-de-hiring技能安装，保留Git关联便于后续拉取；若已有安装，先核对并备份迁移。”

安装后在新会话使用`$product-de-hiring`。若当前技能列表未刷新，重新打开会话。

## 拉取更新

```bash
git -C "$HOME/.codex/skills/product-de-hiring" pull --ff-only
```

`--ff-only`避免自动产生合并提交；如果本地修改与远端更新冲突，保留改动并先核对，不使用强制重置覆盖。技能不会自行定时更新；按需拉取并在新会话使用新版本。

可以直接告诉Codex：“从GitHub更新product-de-hiring技能，先核对本地修改，保留未提交内容。”招聘记录、岗位画像实例与生成报告应保存在部门工作目录中，不存入此技能仓库，避免与规则更新混杂。

## 首次使用

最短开场：“使用$product-de-hiring，帮我筛选这些简历，JD和简历在这个目录。”

没有正式JD也可说明产品服务谁、解决什么问题、此人负责什么，由技能整理岗位画像。技能按当前任务提示必要材料，复用已提供内容，通常每轮只补问1–3个关键问题。

技能会结合已有描述给出有区分度的选项，可多选、自由补充或暂不确定；信息足够便开始当前任务，不连续重写整份画像。用来说明期待的功能例子不会自动变成既定路线或招聘门槛。

v0.4增加贯穿四环节的要求分层：核心要求、其他必需、可培养、加分。先明确具体任务的最低表现与验证方式，再安排筛选重点、面试深度和面后决策。产品/业务是能力边界，核心/加分是岗位优先级，两者分别记录；七项不平均打分，加分不抵消关键缺口，也不因没有加分拒绝。详见[要求分层规则](references/role-priorities.md)。

岗位澄清先看主要决策与验收责任：是否以产品判断为核心，业务知识需要到什么深度、由谁提供专业结论。筛选和面后报告分别回答产品核心、必要业务知识及其他职责是否有证据支持；行业资历或业务业绩不抵消关键产品缺口，产品强项也不抵消真实的必要业务条件。

| 当前环节 | 最少输入 |
| --- | --- |
| 简历筛选 | 岗位依据＋候选人履历材料 |
| 候选人专属面试准备 | 岗位依据＋候选人履历/项目/已有记录之一；缺候选人材料可先做通用提纲 |
| 面试后评估 | 岗位依据＋可辨发言人、包含实际问题和回答的记录；简历有则补充 |
| JD修订/起草 | 现行JD或岗位背景；招聘反馈有则提供 |

## 维护与版本

维护者修改技能、引用资料或模板后，更新版本记录并检查：

```bash
python3 scripts/read_model.py --verify
```

有候选人接续记录时，可在其所在工作目录按实际路径运行`scripts/case_tools.py check`。它只检查记录结构及引用，不判断事实真伪或候选人是否合适。安装环境提供`skill-creator`时，可再运行其`quick_validate.py`检查技能入口。

维护更新使用命令行Git提交、推送到main，不使用网页上传；检查远端新提交并保留其他修改，不强制覆盖历史。检查通过后，可按以下方式提交（路径与版本按本次更新填写）：

```bash
git diff --check
git add SKILL.md references assets scripts docs README.md CHANGELOG.md
git commit -m "Describe the hiring workflow update"
git push origin main
```

版本发布使用命令行创建标签并推送，需要发布说明时使用GitHub命令行工具。登录或连接失败时保留本地修改并解决具体阻碍，不改用网页上传。使用者随后可按上文拉取。团队需要复查历史判断时，记录当时的技能版本、能力模型版本、岗位画像版本和Git提交号。仅拉取规则更新不会重写已有评估。

本仓库不包含真实候选人简历、纪要、评价或内部业务数据。维护时只提交通用规则、空白模板、虚构案例与明确的能力来源；不要把工作目录整体提交进来。

## 能力依据与使用边界

随包能力来源快照为313页汇编：总纲V0.2、P1 V1.1、P2–P7 V1.0，构建于2026-08-31。招聘流程、行为锚点、证据状态和决策方式属于应用建议，不是原模型定义或已发布的公司招聘制度。
