# 模式三：面试后评估

## 从原始材料重新建立证据

1. 按 `intake.md` 核对岗位依据及包含具体回答的实际问答记录；简历、计划和作品有则一并读，缺简历不阻碍评估已观察回答。核对候选人和面试轮次，保留来源完整性；有旧评价时先提取原始证据，再对照旧判断，避免继承偏见。只有结论性评语时先补原始问答，不据此判断能力。
2. 区分候选人与面试官、事实与摘要评价，标时间/段落。对影响去留的片段阅读前后文：是否未给事实、是否追问过、是否提供了解法、是否中断了回答。
3. 更新证据记录。历史自述、现场推演、作品和数据分别记录；同一项目规划与上线结果不得混用。
4. 先做实际覆盖表，再按七项评估。P3/P7没给具体产物走查机会时，即使交流顺畅/不顺畅，也不能据此评其产品语义或感知体验能力。
5. 单独检查岗位额外职责与条件。强证据不能掩盖另一项关键岗位不匹配；同样不能因未观察就给否定判断。

## 输出结构

开头直接写：**针对哪个岗位版本，建议继续/先补证/当前不建议继续；最关键的2–3条理由；结论限于什么材料和范围。**

随后依次提供：

| 区块 | 必须回答 |
| --- | --- |
| 实际覆盖 | 哪些任务被问到、追问多深、哪些未问/纪要缺失？是否有明显提示？ |
| 七项能力 | 每项状态、原始证据ID与位置、判断解释、相反证据、未知及岗位影响 |
| 业务要求 | 指标定义、基线/周期、个人贡献和核验状态；交付与协同的具体证据 |
| 去留依据 | 哪些是关键不匹配，哪些仅是补证；为何足以/不足以支持下一步 |
| 最小下一步 | 只补会改变决策的事项，给时长、任务和希望新增的证据；明确无法由本次纪要判断的部分 |

使用“在该题及追问中未说明……，对本岗位的……构成风险”而非“没有能力/思维不行”。不将态度、表达风格、对组织的抱怨直接转化成能力判断；如涉及协作，只评具体决策、行为与结果。

对同一表现可能有两种解释时，给区分办法。例如，遗漏恢复过程可能是能力缺口，也可能是面试一直只问成功路径；核对实际追问后再定状态。反对面试官方案不是负面证据，应看其替代方案是否满足同一用户目标和约束。

## 比较与接续

比较候选人时，先保证岗位画像版本、核心场景事实及观察机会可比。对“某候选人讲得更多”与“某候选人确有更强证据”分开；不同项目不机械比DAU或团队规模。

记录结论与日期，不覆盖原轮次。补面后把新证据与原缺口对应，说明哪些判断改变、哪些未变。若下一轮岗位要求变化，明确新画像下需要重看哪些证据，不追溯改写原面试表现。

给JD修订的反馈要脱离个人标签，记录：岗位原要求是否清晰、面试机会是否充分、实际反复出现的关键差距、当前样本限制。不能把某个人的弱项直接升级为新的通用硬门槛。
