## 来源层级

1. `sources/product-de-model.pdf`：原始313页能力汇编；总纲V0.2、P1 V1.1、P2–P7 V1.0，构建于2026-08-31。
2. `sources/product-de-model.md`：同一PDF的完整阅读转录，保留原PDF页锚点。文字、表格疑义回PDF核对。
3. 本技能：2026-11-13更新的招聘应用v0.4.4；证据状态、岗位画像、面试安排和决策规则均为据此推演的建议。具体方向和要求由使用方引导形成，未修改模型定义与四类证据状态。

文件来源和SHA256见 `sources/manifest.json`。随包保存快照使部门使用同一版本；不能将快照等同于永远最新。新资料出现时核对修订范围、日期、继承关系；只更新经确认的新版本，并保留旧评估的版本号。不要仅凭文件名“最新”或文件时间选择定义。

原件及完整转录中的产品、行业和技术案例保留原貌，只用于解释能力及专业边界，不提供默认招聘方向。读取定义后，须回到使用方本次提供的用户、任务和岗位要求选择观察方式；不能把原件中的场景、功能、指标或成功解法写成使用方JD，也不能因候选人没做过原件案例所属方向而拒绝。

等级框架、通用DE/TE、历史讨论没有随包混入。需要定级时另取用户适用框架并说明草案/项目内/正式制度状态，不能将本技能证据状态换算成D4–D8。

## 招聘中的观察入口（应用建议）

| 能力 | 自然观察入口 | 不能冒充充分证据的表现 |
| --- | --- | --- |
| P1 | 为谁解决什么；核心对象与规则；约束冲突；边界、合法变化及取舍；领域事实如何转入产品 | 页面流程图、数据表、功能数量、使用了某模型 |
| P2 | 用户当时知道什么、担心什么、为什么犹豫；如何形成真实预期并保留自主判断 | 通用用户画像、操纵点击、只有一句提示 |
| P3 | 实际概念、命名、状态文字与关键内容是否一致；用户能否理解事实及下一步 | 面试口才、写漂亮文案、字体美观 |
| P4 | 如何分类、组织、定位、到达、返回；设备与规模变化时能否找到内容 | 只会画页面、菜单越全越好 |
| P5 | 一次操作的意图、表达、响应、结果确认、纠错/恢复闭环 | 有按钮、有弹窗或实现自动执行 |
| P6 | 等待、分阶段完成、离开再回、中断、部分失败、异步结果如何连续 | 缓存、内存、响应速度等工程词汇本身 |
| P7 | 感知主次、强度、整体品质、一致性、可读性与实际使用环境的验收 | 会设计工具、品牌审美、要求PM独立完成专业设计制作 |

同一设计可能涉及多项能力。标主责并解释关联，不能把一条宽泛的“重视用户体验”重复当作七项强证据。不要以同一种极简风格、固定交互形式或面试官偏好代表模型要求。七原则与七能力是不同层次、多对多关系。
