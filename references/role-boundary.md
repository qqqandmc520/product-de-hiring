# 产品领域与业务领域：招聘边界

这是招聘应用规则。模型依据为原PDF第14、20、36–38页；分类、问法与报告结构为据此推演，不是新增能力或公司职级制度。

## 1. 先问这个人要独立判断什么

从岗位的主要决策、日常产物、验收对象及失败责任判断，名称和行业只作背景。

| 工作重心 | 识别依据 | 本技能如何处理 |
| --- | --- | --- |
| 产品主导 | 主要对用户任务、价值取舍、产品规则及完整使用体验形成独立判断，并验收产品结果 | 用七项能力作核心依据；业务知识、增长、管理等按岗位另验 |
| 业务主导 | 主要形成来源业务领域的专业结论或经营决策；产品主要承载其结论 | 明确本技能不能认证业务专业性，建议相应领域评估者参与；可先整理岗位或产品相关证据 |
| 复合岗位 | 同时独立承担产品判断与明确的业务/经营责任，两边都有决策及验收要求 | 写清主责和两边最低要求、资源与验收人；若认定为产品DE招聘，产品能力仍为核心、不可被业务业绩抵消 |
| 尚不明确 | 只有头衔、泛化“懂业务”或目标，不能分辨实际判断责任 | 提一个有区分度的问题，画像标暂定；可继续整理，不给确定的产品岗位适配结论 |

不要要求用户先学分类。已有事实能说明时先写判断及依据；事实互相冲突、且会改变筛选标准时再补问。例如：

“从你说的亲自取舍方案和验收体验看，我暂按产品能力为核心理解。业务侧希望他做到哪一步：①理解规则并与专家核对，②已有行业经验能直接判断常见问题，③独立制定专业标准并对专业结论负责？可以组合，也可说还没定。”

若用户强调既要经营又要产品，不擅自缩成体验专员；若实际业务主导但称“产品专家”，解释责任差异并保留用户的招聘目标，不强行改名。

## 2. 业务知识有必要，但要定义“必要到哪里”

对每项会影响岗位决策的业务知识，记录：任务与错误后果、需理解的规则/因果/约束、谁提供及验收专业结论、入职即需/可培养/加分、验证方式。只记录本岗实际需要的项；不能将任何特定行业、技术或业务经历自动变成岗位门槛。

用三个层次澄清，而非让用户填知识百科：

- **足以产品化的理解**：能够识别关键对象、硬约束、软偏好、例外、不确定性和知识缺口，向合适的专家核实，并转成规则、信息、用户控制与结果说明。这是P1的领域理解与产品化转译，结合其余六项看使用体验。
- **岗位必需的已有知识**：只在使用方明确任务确需时，说明具体知识范围、为何无法通过资源/学习补齐及验证办法；列为独立岗位条件。不能仅用做过某类产品替代知识验证。
- **独立专业裁决**：若职责涉及制定来源领域专业标准或独立裁决专业事实，需明确来源领域责任和相应专业评估；不能拿七项产品能力推导其资格。

P1转译看“理解并澄清什么、如何进入产品、如何保持原意”，不是背行业题，也不是只说“我会问专家”。没有给必要事实时先允许提问或明确假设；补齐事实后再观察其是否能独立完成产品判断。拒绝编造专业事实可以是正向边界线索，但不自动证明转译能力。

## 3. 四环节都保留双向检查

- **筛选**：行业/经营自述与产品判断线索分开。强行业背景但产品线索少，写待验证或依据岗位约束给阶段建议，不能直接判产品强，也不能仅因简历没写就判产品弱。跨行业但有产品证据，核对必要领域理解能否迁移/补齐，不自动拒绝。
- **面试**：同一案例分别追问“专业事实依据和责任人是什么”与“你亲自决定哪些产品取舍、用户怎样理解并完成任务”。使用已给统一专业事实的迁移题；确属岗位硬要求的专业知识另设验证并说明评估边界。
- **面后**：先说明本岗位为何产品主导/复合，再分别判断产品核心、必要业务知识及其他职责。产品核心有已观察关键缺口时，不以行业资历/商业业绩补偿；产品证据不足时写不足并给阶段建议，不能改称候选人永久属于某类专家。业务知识不足同样不能被产品强项掩盖。
- **JD修订**：把产品使命、亲自判断和体验验收写清；“懂业务”改成具体任务、深度与来源责任。保留真实经营责任；业务专业裁决如确需则单列，不藏在“产品专家”之下。

## 4. 必须可见的结论

本节的“产品核心”描述招聘属性；具体任务优先级另按 `role-priorities.md` 分核心要求、其他必需、可培养、加分，两者不能混为一谈。必要业务知识不自动全是核心，增长可为核心职责但仍是独立R:要求；产品DE招聘的产品判断主责不能被挤掉。

岗位画像中保留：**岗位属性及依据；产品核心表现；必要业务知识与责任边界；会改变标准的未知**。

筛选/面后报告的开头用少量自然文字明确：

1. 本次是否按产品能力为核心招聘，依据是什么；若暂不明确，结论受什么限制。
2. 本轮候选人证据主要体现产品判断、来源领域判断、经营协同还是混合；引用具体行为，不以头衔分类。
3. 产品核心：支持/部分支持/已观察关键缺口/未充分观察；必要业务知识及其他职责分别给依据和未知。七项详细表仍保留。
4. 当前阶段综合建议。需要补证时同时明确：现有材料是否已支持推进、推进为下一轮验证还是已支持岗位匹配；不让“可以补面”掩盖当前不匹配，也不把未知写成否定。

“推荐参加验证性初试”“建议继续补证”“当前证据支持岗位匹配”不是同一个结论。用户要求仅凭现有材料决策时，保持同一证据与标准，给受限建议；只有新增证据、岗位条件或决策约束变化才解释性调整，不因追问口气改变结论。

## 5. 对照例（虚构，不是候选人模板答案）

某人能形成来源领域专业方案，但只把方案交给其他角色，未展示亲自组织用户任务和体验取舍：可支持相应业务知识，产品能力仍需验证。另一人有具体产品判断证据，但对使用方明确入职即需的专业规则不了解：产品证据与业务缺口同时保留。不能只用“更懂行业”决定产品DE适配；比较任务和门槛须来自本次岗位。
